## 1. Problem Statement

Users frequently store unlabeled cooked meals and raw household leftovers in their freezer that carry no barcode and cannot be tracked via the Feature 1.1 Open Food Facts lookup path. This gap results in forgotten mystery containers, unsafe expiration violations, and avoidable food waste across the household. Feature 1.2 closes this gap by introducing a camera-driven ingestion workflow where the Flutter client submits a food container photograph to a FastAPI multipart endpoint, which forwards the validated image payload to the `gemini-1.5-flash` multimodal API, parses a structured JSON response against a strict Pydantic v2 schema, and commits a new `inventory_items` row with `upc = NULL` and a server-computed `expiration_date` derived from the model's `estimated_shelf_life_days` field — all while writing a corresponding audit record to `ai_audit_logs` for accuracy monitoring.

---

## 2. Goals

- Expose a production-grade `POST /inventory/scan-leftover` endpoint accepting `multipart/form-data` image uploads with enforced MIME type whitelisting and a hard 10 MB payload ceiling.
- Forward validated image bytes to `gemini-1.5-flash` using the `google-generativeai` SDK with JSON-mode `response_mime_type` to guarantee structured output without markdown fence stripping.
- Parse and validate the Gemini response against a strict Pydantic v2 `GeminiVisionResult` schema before any database interaction occurs — failures at this layer return `422` without touching the DB.
- Commit the parsed result to `inventory_items` with `upc = NULL`, `source_type = "image_scan"`, and an application-computed `expiration_date` set to `date.today() + timedelta(days=estimated_shelf_life_days)`.
- Write a corresponding row to `ai_audit_logs` capturing model name, raw prompt, truncated raw response, parsed item name, and confidence score in the same database transaction as the `inventory_items` insert.

---

## 3. Non-Goals

- This feature does NOT handle real-time streaming video or burst-mode multi-frame analysis.
- This feature does NOT perform multi-object detection within a single image; one request ingests exactly one inventory item.
- This feature does NOT implement client-side image compression or resizing — the Flutter client is responsible for keeping uploads under the 10 MB server-side ceiling.
- This feature does NOT expose a user feedback loop for correcting AI-misidentified items (reserved for a future correction endpoint).
- This feature does NOT detect or extract UPC barcodes visible within the submitted image — that path belongs exclusively to Feature 1.1.

---

## 4. Personas & User Stories

- **As a User**, I want to photograph my leftover lasagna container so that the app automatically logs it in my freezer inventory without requiring me to type a single character.
- **As a Developer**, I want every Gemini API interaction recorded in `ai_audit_logs` with the raw prompt, raw response, and confidence score so I can audit model accuracy over time and iterate on the system prompt without guessing.

## 5. Functional Requirements

- **FR-1.** The system MUST expose `POST /inventory/scan-leftover` accepting a `multipart/form-data` request body with a single required field `image` of type `UploadFile`. The route MUST be registered on the `inventory` `APIRouter` with `status_code=status.HTTP_201_CREATED`, `response_model=LeftoverScanResponse`, `tags=["Inventory — Ingestion"]`, and `summary="Scan a food container image via Gemini Vision and log to freezer inventory."`. The endpoint function MUST be declared `async def`.

- **FR-2.** The system MUST validate `image.content_type` against the whitelist `{"image/jpeg", "image/png", "image/webp", "image/heic"}` as the very first operation. If `image.content_type` is absent or not in the whitelist, the endpoint MUST immediately raise `HTTPException(status_code=415, detail="Unsupported image type. Accepted: image/jpeg, image/png, image/webp, image/heic.")` without reading any file bytes or making any external API calls.

- **FR-3.** The system MUST read image content via `image_bytes: bytes = await image.read()` and enforce a maximum payload size of **10,485,760 bytes (10 MB)**. If `len(image_bytes) > 10_485_760`, the endpoint MUST raise `HTTPException(status_code=413, detail="Image payload exceeds the 10 MB limit. Please resize the image client-side before submitting.")` without forwarding bytes to the Gemini API.

- **FR-4.** The system MUST construct an inline image data part as `{"mime_type": image.content_type, "data": image_bytes}` and invoke the Gemini model via `await model.generate_content_async([GEMINI_SYSTEM_PROMPT, image_part])`. The model instance MUST be pre-configured as `genai.GenerativeModel("gemini-1.5-flash", generation_config=genai.GenerationConfig(temperature=0.1, max_output_tokens=512, response_mime_type="application/json"))`. `genai.configure(api_key=settings.GEMINI_API_KEY)` MUST be called once at application startup in `backend/app/main.py` — never per-request.

- **FR-5.** The system MUST wrap the `generate_content_async` call in `asyncio.wait_for(..., timeout=15.0)`. If `asyncio.TimeoutError` is raised, the system MUST log at `ERROR` level and raise `HTTPException(status_code=503, detail="Gemini Vision API timed out. Please retry.")`. If the SDK raises `google.api_core.exceptions.GoogleAPIError`, the system MUST catch it, log the exception class name at `ERROR` level, and raise `HTTPException(status_code=503, detail="Gemini Vision API unavailable. Please retry.")`. In **both** error cases, zero rows MUST be written to `inventory_items` or `ai_audit_logs`.

- **FR-6.** The system MUST attempt `parsed_dict = json.loads(response.text)`. If `json.loads()` raises `json.JSONDecodeError`, the system MUST raise `HTTPException(status_code=422, detail=f"Gemini returned malformed JSON. Raw response (truncated): {response.text[:300]}")`. This exception MUST be raised before any SQLAlchemy session interaction.

- **FR-7.** The system MUST validate the parsed dictionary via `gemini_result = GeminiVisionResult.model_validate(parsed_dict)`. If Pydantic raises `ValidationError`, the system MUST raise `HTTPException(status_code=422, detail="Gemini response did not conform to the required schema. Check ai_audit_logs for the raw response.")` without writing to the database.

- **FR-8.** The system MUST apply a confidence score gate: if `gemini_result.confidence_score is not None` and `gemini_result.confidence_score < 0.40`, the `product_name` written to `inventory_items` MUST be overridden to the string `"Unknown Food Item"` and a `WARNING`-level log line MUST be emitted: `f"Low Gemini confidence ({gemini_result.confidence_score:.2f}) for image scan. Defaulting product_name to 'Unknown Food Item'."`. The `confidence_score` value itself MUST still be stored as-is in `ai_audit_logs`.

- **FR-9.** The system MUST write exactly one row to `inventory_items` using the following explicit field mapping:

  | `inventory_items` Column | Value Source |
  |---|---|
  | `upc` | `None` — **hardcoded `NULL`; never populated by this endpoint** |
  | `product_name` | `gemini_result.item_name` (or `"Unknown Food Item"` per FR-8) |
  | `estimated_shelf_life_days` | `gemini_result.estimated_shelf_life_days` |
  | `expiration_date` | `date.today() + timedelta(days=gemini_result.estimated_shelf_life_days)` — computed application-side |
  | `quantity_description` | `gemini_result.quantity_description` (nullable — `None` if absent) |
  | `source_type` | `"image_scan"` — hardcoded enum literal |
  | `notes` | `gemini_result.notes` (nullable — `None` if absent) |
  | `is_consumed` | `False` — hardcoded default |
  | `created_at` | MySQL server-side `DEFAULT CURRENT_TIMESTAMP` — **never set application-side** |

- **FR-10.** Immediately after `db.flush()` exposes the auto-assigned `item_id`, the system MUST write exactly one row to `ai_audit_logs` within the **same database transaction** as the `inventory_items` INSERT. The `ai_audit_logs` row MUST contain: `item_id` (FK to the flushed `InventoryItem.item_id`), `model_name="gemini-1.5-flash"`, `raw_prompt` (the full `GEMINI_SYSTEM_PROMPT` string constant), `raw_response=response.text[:2000]` (truncated to 2000 characters), `parsed_item_name=gemini_result.item_name`, `confidence_score=gemini_result.confidence_score`, and `status="success"`. A single `db.commit()` MUST follow both `db.add()` calls — atomic or nothing.

- **FR-11.** The system MUST emit structured log lines via Python's `logging` module (surfaced in Uvicorn stdout) at the following levels:
  - `INFO` on successful Gemini response receipt: `f"Gemini scan success: item='{name}', confidence={score}, payload_bytes={n}"`
  - `INFO` on successful DB commit: `f"inventory_items INSERT committed: item_id={id}, source_type='image_scan'"`
  - `WARNING` when confidence falls below 0.40 threshold (per FR-8).
  - `ERROR` on any Gemini API exception, including the exception class name and truncated message.

- **FR-12.** The system MUST obtain the SQLAlchemy `Session` exclusively via `db: Session = Depends(get_db)` dependency injection. No module-level `SessionLocal()` calls, no global session state, no session persistence between requests. All DB operations MUST be wrapped in a `try/except/finally` block where the `except` path calls `db.rollback()` and re-raises the original `HTTPException`, and the `finally` path is handled by the `get_db()` context manager.

## 6. Non-Functional Requirements

- **Performance:** The endpoint MUST return a response within **20 seconds** end-to-end (image read + Gemini latency + DB write). The `asyncio.wait_for()` Gemini timeout is set at 15 seconds, providing 5 seconds of headroom for I/O and DB operations. File size validation (FR-3) MUST complete in < 50 ms.
- **Security:** `GEMINI_API_KEY` MUST be loaded exclusively from `backend/.env` via `pydantic-settings` (`class Settings(BaseSettings)`). It MUST NOT appear in any log line, HTTP response body, error `detail` string, or version-controlled file. All `settings.*` references are read-only at runtime.
- **Observability:** Every request MUST produce at minimum four Uvicorn log lines covering: (1) incoming MIME type and `len(image_bytes)`, (2) Gemini API call outcome (success, timeout, or error class), (3) Pydantic validation outcome and `confidence_score`, and (4) `item_id` assigned on successful DB commit, or the failure stage and returned HTTP status code.

---

## 7. Acceptance Criteria

- **AC-1.** Given a valid JPEG photograph of a soup container, when `POST /inventory/scan-leftover` is called with the image as `multipart/form-data`, then the server returns HTTP `201 Created` with a JSON body containing a non-null integer `item_id`, a `product_name` of `"Soup"` (or an equivalent AI-inferred food name), `"upc": null`, `"source_type": "image_scan"`, and a future `expiration_date`. A row MUST exist in both `inventory_items` and `ai_audit_logs` in the live `fp-mysql` database after the call.

- **AC-2.** Given an upload of a `.pdf` file (MIME type `application/pdf`), when the endpoint is called, then the server returns HTTP `415 Unsupported Media Type` and zero rows are written to `inventory_items` or `ai_audit_logs`.

- **AC-3.** Given an image file with `len(bytes) > 10_485_760`, when the endpoint is called, then the server returns HTTP `413 Request Entity Too Large` and zero rows are written to any database table.

- **AC-4.** Given a valid image upload where Gemini returns the plain text string `"I see a container with food"` instead of a JSON object, then the server returns HTTP `422 Unprocessable Entity` with the truncated raw string present in the `"detail"` field of the JSON error body.

- **AC-5.** Given a successful Gemini scan where the returned `confidence_score` is `0.25`, then the `inventory_items` row committed to MySQL has `product_name = "Unknown Food Item"`, the `ai_audit_logs` row has `confidence_score = 0.25`, and the Uvicorn log contains a `WARNING` line referencing the sub-threshold confidence value.

- **AC-6.** Given the Gemini API is unreachable or raises `GoogleAPIError`, when the endpoint is called, then the server returns HTTP `503 Service Unavailable` and the `inventory_items` and `ai_audit_logs` row counts are identical to their pre-request state (zero writes occurred).

### Table: `ai_audit_logs` — New Table Created by This Feature

```python
# backend/app/models/ai_audit_log.py
from sqlalchemy import (
    Integer, VARCHAR, TEXT, Float, DateTime,
    Enum as SAEnum, ForeignKey, Index, func
)
from sqlalchemy.orm import Mapped, mapped_column, relationship
from typing import Optional, TYPE_CHECKING
from datetime import datetime
from app.db.base import Base

if TYPE_CHECKING:
    from app.models.inventory import InventoryItem


class AIAuditLog(Base):
    __tablename__ = "ai_audit_logs"

    log_id: Mapped[int] = mapped_column(
        Integer, primary_key=True, autoincrement=True
    )
    item_id: Mapped[Optional[int]] = mapped_column(
        Integer,
        ForeignKey("inventory_items.item_id", ondelete="SET NULL"),
        nullable=True   # SET NULL: audit records persist if the parent item is deleted
    )
    model_name: Mapped[str] = mapped_column(VARCHAR(100), nullable=False)      # e.g. "gemini-1.5-flash"
    raw_prompt: Mapped[str] = mapped_column(TEXT, nullable=False)               # Full system prompt string
    raw_response: Mapped[Optional[str]] = mapped_column(TEXT, nullable=True)    # Truncated to 2000 chars
    parsed_item_name: Mapped[Optional[str]] = mapped_column(VARCHAR(255), nullable=True)
    confidence_score: Mapped[Optional[float]] = mapped_column(Float(precision=4), nullable=True)
    status: Mapped[str] = mapped_column(
        SAEnum("success", "parse_error", "api_error", name="audit_status_enum"),
        nullable=False
    )
    created_at: Mapped[datetime] = mapped_column(
        DateTime, server_default=func.current_timestamp(), nullable=False
    )

    inventory_item: Mapped[Optional["InventoryItem"]] = relationship(
        "InventoryItem", foreign_keys=[item_id]
    )

    __table_args__ = (
        Index("ix_ai_audit_logs_item_id", "item_id"),
        Index("ix_ai_audit_logs_model_name", "model_name"),
        Index("ix_ai_audit_logs_status", "status"),
    )
```

**Key Constraints:**
- `ai_audit_logs.item_id` uses `ondelete="SET NULL"` — audit records persist independently even if the parent `inventory_items` row is deleted.
- `inventory_items.upc` MUST remain `nullable=True`. This endpoint **always** writes `NULL` to that column.
- Both PKs are isolated auto-increment (`item_id`, `log_id`). No composite keys.
- Both `inventory_items` INSERT and `ai_audit_logs` INSERT MUST be committed in a single `db.commit()` call to guarantee atomicity.

## 11. AI / ML Considerations

**Model:** `gemini-1.5-flash`
**SDK Package:** `google-generativeai` (`pip install google-generativeai>=0.7.0`)

**SDK Configuration:**
```python
# backend/app/core/gemini.py
import google.generativeai as genai
from app.core.settings import settings

def configure_gemini() -> None:
    """Called once at application startup in main.py lifespan."""
    genai.configure(api_key=settings.GEMINI_API_KEY)

VISION_MODEL = genai.GenerativeModel(
    model_name="gemini-1.5-flash",
    generation_config=genai.GenerationConfig(
        temperature=0.1,                     # Deterministic structured output
        max_output_tokens=512,               # Sufficient for the schema; prevents runaway responses
        response_mime_type="application/json", # JSON mode: bypasses markdown fence stripping
    ),
)
```

**System Prompt (verbatim constant — stored in `backend/app/services/gemini_vision.py`):**
```
You are a food identification assistant integrated into a home freezer inventory management
system called Freezer Penguin. Analyze the provided image of a food storage container and
identify the food contents with as much specificity as possible.

You MUST return ONLY a valid JSON object — no markdown code fences, no preamble text,
no trailing explanations. The response must be parseable by json.loads() with no preprocessing.

The JSON MUST conform to this exact schema:
{
  "item_name": "<string: most specific food name, e.g. 'Chicken Tikka Masala', max 255 chars>",
  "estimated_shelf_life_days": <integer: safe freezer storage in days from today, range 1-3650>,
  "quantity_description": "<string or null: volume/weight estimate, e.g. '2 cups', '500g', '1 portion'>",
  "confidence_score": <float: your identification confidence, range 0.00-1.00>,
  "notes": "<string or null: observations about container or food state, max 500 chars>"
}

Safety rule: If confidence_score < 0.40, still return the full valid JSON object
but set item_name to "Unknown Food Item".
```

**Fallback Strategy:**
- `confidence_score < 0.40` → Override `product_name` to `"Unknown Food Item"` application-side (FR-8). Do NOT re-prompt Gemini.
- `JSONDecodeError` on `response.text` → HTTP `422`. Log raw response at `WARNING`.
- `GoogleAPIError` or `asyncio.TimeoutError` → HTTP `503`. Zero DB writes.

**Cost Boundary:** `gemini-1.5-flash` at 512 `max_output_tokens` per call. At current pricing, each scan costs < $0.001. No streaming, no batching required at this development scale.

## 14. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Low-light or blurry images degrade Gemini identification quality | Medium | Medium | Confidence score gate (FR-8): items below 0.40 default to `"Unknown Food Item"`. `ai_audit_logs` enables offline auditing of failure patterns. |
| Gemini returns structurally valid JSON but semantically wrong food names (e.g., `"A plastic container"`) | Medium | Low | `confidence_score` in `ai_audit_logs` flags low-certainty records for manual review. Future correction endpoint can patch `product_name`. |
| `response_mime_type="application/json"` unsupported in older SDK versions | Low | High | Pin `google-generativeai>=0.7.0` in `requirements.txt`. If JSON mode is unavailable at runtime, the fallback is to strip ` ```json ` fences from `response.text` before calling `json.loads()`. |
| `ai_audit_logs` INSERT fails after `inventory_items` INSERT flushes | Low | High | Both `db.add()` calls MUST precede a single `db.commit()`. Any exception on the `ai_audit_logs` add triggers `db.rollback()`, rolling back the `inventory_items` insert atomically. |
| 4K smartphone images routinely exceed 10 MB limit | High | Medium | Document the 10 MB ceiling in the Flutter client's integration spec. Add a `max_upload_size` middleware in `backend/app/main.py` as a secondary defense layer. |
